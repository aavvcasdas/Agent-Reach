# 03｜生产与发布 SOP

## 1. 每日流程

### 第一步：收集真实输入（调研）

复制 `templates/每日制作单.md`，先填三样输入：

1. 上一期真实评论与任务回答；
2. 上一期真实数据；
3. 与受众相关的热点或竞品公开内容，并保存原始链接。

使用 Agent Reach 时可按项目文档执行：

```bash
agent-reach doctor --json
bili search "你的选题关键词" --type video -n 10
bili video BVxxxxxxxxx
```

如果某个后端不可用，按项目提供的备选网页读取路径处理；不要绕过登录、验证码或平台风控。竞品只看选题结构、节奏和互动方式，不复制台词、画面、角色或封面。

### 第二步：生成三个候选选题

把角色设定、真实评论、数据和资料链接放入 `04-AI提示词.md` 的“每日选题提示词”。

人工按五项各打 1–5 分：

- 是否符合“开坑→交付”的角色主线；
- 是否承接上期评论或剧情；
- 前 3 秒是否能看懂冲突；
- 事实与素材风险是否可控；
- 今天是否能实际完成。

不要默认采用模型推荐项；分数相近时，优先选择制作更简单、互动更明确的一个。

### 第三步：写 60–90 秒脚本

固定结构：

```text
0–3 秒：具体事故或反差
3–15 秒：今天唯一任务
15–50 秒：尝试与一次分叉
50–70 秒：删减、合并或承认失败
最后 5–10 秒：一个评论任务
```

规则：

- 一期只讲一个核心冲突；
- 一次最多两个主要笑点；
- 只有真实发生的审核、评论和数据才能写成事实；
- 虚构剧情可以存在，但发布简介必须标注；
- 不为了押时长而重复解释人设。

### 第四步：生产素材

1. 以用户指定的 `assets/gemini-user-selected.png` 为统一角色原图，不自行生成或重绘；
2. 首周只使用该原图进行排版、缩放和位置动效；需要新表情时，先取得对应素材及授权；
3. 用简单位移、缩放和企划窗口表现剧情；
4. 使用有权限的配音、字体、音乐和音效；
5. 字幕逐句人工校对，尤其是名词、数字和来源名称。

不要一开始投入 Live2D 或复杂动画。先验证观众是否愿意参与，再升级制作。

### 第五步：人工审核

发布前逐项确认：

- [ ] 标题和开头表达的是同一件事，没有夸大；
- [ ] 评论、投票、退稿、数据和“AI做了什么”均按事实披露；
- [ ] 热点事实有原始来源，观点与事实分开；
- [ ] 不包含未核实的产品能力或官方身份声明；
- [ ] 角色、图片、配音、音乐、字体和截图可以合法使用；
- [ ] 评论昵称和头像按需匿名化，不曝光无关个人信息；
- [ ] 按平台要求标注 AI 辅助生成、二创和虚构剧情；
- [ ] 结尾只有一个主要互动任务；
- [ ] 下期能够兑现这个任务；
- [ ] 人工看完最终成片，而不只是审脚本。

### 第六步：人工发布

- 账号登录、凭证和最终发布操作由你本人控制；
- 固定一个自己能持续的时间，不迷信通用“最佳发布时间”；
- 简介写清本期任务、必要来源和身份说明；
- 标签控制在直接相关的少量词，例如 `AI运营`、`虚拟UP主`、`运营日记`；
- 不购买、不组织虚假播放、评论或投票。

### 第七步：评论承接

发布后安排一次集中查看评论：

- 优先回复提供了具体任务、具体修改意见或可靠来源的评论；
- 对下期将采纳的评论做好记录；
- 采用时署名或匿名引用，并说明为什么选它；
- 如果有效评论不足，明确说“本期有效评论不足，按预告的默认路线执行”；
- 不把点赞最高等同于事实正确，涉及事实仍需核查。

### 第八步：24 小时复盘

把数据填入 `data/每日数据复盘.csv`，然后只写一个主要修正动作。

建议计算：

```text
每千播放评论数 = 评论数 ÷ 播放量 × 1000
每千播放涨粉数 = 净增关注 ÷ 播放量 × 1000
任务回答率 = 回答互动任务的人数 ÷ 有效评论人数
```

“任务回答率”需要人工去重和分类，样本太少时只记录原始数量，不强行计算百分比。

## 2. 数据判断

| 现象 | 优先调整 |
|---|---|
| 播放高、关注低 | 强化置顶实验规则与下期承诺 |
| 完播低 | 删除开头背景介绍，先出事故 |
| 评论多但无人回答任务 | 把问题改成 A/B 或一个具体动作 |
| 评论被采纳后回访增加 | 保持署名反馈，继续评论主线 |
| 只有热点有流量 | 增加热点栏目，但保留角色冲突 |
| 制作时间持续增加 | 减少素材与场景，回到轻动画 |

不要凭一条视频总结规律。至少比较数日，并与本号中位数对照。

## 3. 文件管理

每天建一个工作目录：

```text
Day-01/
├── 01-调研与来源.md
├── 02-选题.md
├── 03-脚本-v1.md
├── 04-脚本-发布版.md
├── 05-素材清单.md
├── 06-发布信息.md
└── 07-24小时复盘.md
```

发布版与数据表中的标题保持一致，方便后续查找。任何自动生成的文件都不能因为文件名是“发布版”就跳过人工审核。

## 4. 首周最低可行配置

- 一张用户指定且来源信息已记录的角色原图；
- 不自行生成新表情，必要时先补充已授权素材；
- 一个片头模板，时长不超过 1 秒，最好没有片头；
- 一个配音音色；
- 一个字幕样式；
- 一个 A/B 评论互动模板；
- 一张真实数据表。

先完成七轮“发布—评论—兑现—复盘”，再考虑自动化或复杂动画。
